Step 2 / install the thin CLI

Start from a supported fresh machine.

Release binaries support Linux and macOS on AMD64 or ARM64. The locked skill installer needs Git, Node.js, and npm. The CLI installer needs a POSIX shell, curl, jq, and either sha256sum or shasum. Before installing the supervised pair, install Perl with Time::HiRes; Linux must expose CLOCK_BOOTTIME and macOS CLOCK_MONOTONIC_RAW. The repository's two-agent demo additionally requires Bash and seq.

Ask before installing software. The pinned installer is inspectable, requires GitHub's immutable per-asset digests to agree with the published SHA256SUMS, verifies the binary version, checks every supervisor runtime dependency, and exits before changing the destination when provenance or a dependency is unavailable.

The default destination is /usr/local/bin. The installer creates it when absent and requests sudo only when your account cannot create or write that path. Without sudo, set OCTOSTORE_INSTALL_DIR="$HOME/.local/bin" and add that directory to PATH.

The installer does not start a server or create credentials. It prints a loopback-only first-run recipe that generates a random bearer token in an owner-only file.

Step 4 / couple authority to execution

Do not leave the heartbeat beside an uncoupled worker.

A hold process can report that authority is gone. It cannot reach into an arbitrary agent runtime and undo work by itself.

  1. Start hold before the worker.
  2. Validate schema, kind, name, candidate, and all three authority budget fields.
  3. Subtract the greater of wall-clock authority_observed_unix_ms age and suspend-inclusive authority_observed_continuous_ms same-host age; reject stale events.
  4. Start work only after a fresh leader or acquired.
  5. Cancel or fence work on loss, uncertainty, malformed output, or unexpected exit.

The installer provides octostore-supervisor. It requires jq and Perl with Time::HiRes, arms a detached lifetime guardian before the hold can gain authority, and keeps hold and worker group identities reserved through containment. It publishes terminal lifecycle output only after containment. Keep the hold, supervisor, and worker on the same host; do not relay or persist authority events across machines or boots.

Portable boundary: this is cooperative process-group containment, not a security sandbox. Workers and descendants must not daemonize, call setsid, create another process group, or hand work to another service. Use a dedicated container or cgroup for workers that may detach or cannot be trusted to follow that contract.

Election or lock?
ELECTION

One coordinator for a group

Good for a merge coordinator, scheduler, dispatcher, controller, or singleton maintenance role.

  • Hosted path is account-free
  • Room is one shared coordination address
  • Candidate IDs identify processes, not users
LOCK

One owner for an exact item

Good for issue 1842, deploy production, migrate tenant 7, or another durable work identity.

  • Authenticated hosted or self-hosted boundary
  • Stable key reused across retries
  • Private token file; no --token flag
authenticated supervised exact-item hold

For hosted locks, sign in at the OctoStore dashboard, save the issued bearer credential in an owner-only file, select the hosted authority explicitly, and set AGENT_WORKER to the protected executable.

Machine contract

Parse events, not prose.

Human diagnostics go to stderr. --json writes versioned JSONL to stdout without leader tokens, lease IDs, or bearer credentials.

Safety boundaries

A lease is authority with an expiry—not exactly-once work.

Public is not private. A generated room ID is hard to guess, but anyone who knows it can campaign or inspect current state.

Uncertainty means stop. A timed-out renewal is never converted into success, even if the server may have received it.

Terms need enforcement. Pass the generation to downstream systems that can reject stale writes.

One authority. The supported server is one OctoStore process with one SQLite database, not an HA consensus cluster.

Approval lives elsewhere. Winning a lease never grants permission for a destructive or irreversible action.

Work lives elsewhere. OctoStore does not assign tasks, run prompts, store branches, merge code, or manage a queue.

HTTP is the deeper layer

Need the exact wire contract?

The CLI is optional. Every primitive remains ordinary HTTP with a complete OpenAPI document, stable error codes, retry guidance, request IDs, and bounded best-effort watches.
