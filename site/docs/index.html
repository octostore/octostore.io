Start with the agent surface.

Inspect the plain-text skill, then install the pinned v0.14.4 copy. It tells an agent when to choose an election or lock and when to stop.

skills CLI · pinned release
git clone --branch v0.14.4 --depth 1 https://github.com/octostore/octostore.io
cd octostore.io
npm ci --ignore-scripts --no-audit --no-fund
./node_modules/.bin/skills add \
  https://github.com/octostore/octostore.io/tree/v0.14.4 \
  --skill octostore --agent codex -y

Create one hosted room outside the candidates. Give both agents the same returned ID; only the candidate ID and protected worker change.

installed supervisor · one candidate per agent host
# Create once, then share this exact value.
ROOM=$(octostore election create --json | jq -r .election_id)
export ROOM

# Set a unique ID and protected executable in each agent host.
octostore-supervisor election "$ROOM" "$AGENT_ID" "$AGENT_WORKER" -- \
  octostore election hold "$ROOM" \
    --candidate "$AGENT_ID" --ttl 30 \
    --acquire-timeout 60 --json

Run the template concurrently with different AGENT_ID and AGENT_WORKER values. Exactly one supervisor opens its worker gate; the other waits. Terminal lifecycle output is published only after the protected process groups are contained.

Account-free leader election.

Election rooms are capability-based, not identity-based. The room ID is a shared coordination address. The leader token is the authority to mutate the current term.

raw HTTP · create once, campaign from each candidate
ROOM=$(curl -s -X POST https://api.octostore.io/elections \
  | jq -r .election_id)

curl -s -X POST \
  "https://api.octostore.io/elections/$ROOM/campaign" \
  -H "Content-Type: application/json" \
  -d '{"candidate_id":"worker-a","ttl_seconds":30}'

A winner receives status: "leader", a monotonic term, and a secret leader_token. Followers receive the same current leader and retry_after_ms.

Leader election endpoints
MethodPathPurpose

Renew at half the TTL

shell
curl -s -X POST \
  "https://api.octostore.io/elections/$ROOM/renew" \
  -H "Content-Type: application/json" \
  -d "{\"leader_token\":\"$LEADER_TOKEN\",\"ttl_seconds\":30}"

Public election TTLs range from 5 to 300 seconds. A candidate can renew indefinitely while it is healthy. If it crashes, the room becomes vacant after expiry and a new term can begin.

Resign on a clean shutdown

shell
curl -s -X POST \
  "https://api.octostore.io/elections/$ROOM/resign" \
  -H "Content-Type: application/json" \
  -d "{\"leader_token\":\"$LEADER_TOKEN\"}"

Authenticated task ownership.

Locks are authenticated on both the hosted and self-hosted authorities. For the hosted path, sign in at the OctoStore dashboard, save the issued bearer credential in an owner-only file, and let the CLI own the session and heartbeat lifecycle while the installed supervisor gates the protected worker. Self-host when coordination traffic or identity must stay on your network.

installed supervisor · exact item
chmod 600 /path/to/octostore-token
OCTOSTORE_URL=https://api.octostore.io \
OCTOSTORE_TOKEN_FILE=/path/to/octostore-token \
octostore-supervisor lock "repo/octostore/issue-1842" - "$AGENT_WORKER" -- \
  octostore lock hold "repo/octostore/issue-1842" \
    --ttl 120 --acquire-timeout 60 --json

The CLI emits acquired, waiting, renewed, and terminal loss events without printing the lease or bearer capability. Raw lock responses expose acquired, held, or delayed and a fencing token for downstream stale-write rejection.

Self-host one authority.

Download the v0.14.4 installer, inspect it, and execute the pinned copy. The installer verifies the published SHA-256 checksum and binary version before placing octostore in /usr/local/bin.

pinned, inspectable install
VERSION=v0.14.4
curl -fsSLo octostore-install.sh \
  "https://raw.githubusercontent.com/octostore/octostore.io/$VERSION/install.sh"
cat octostore-install.sh
OCTOSTORE_VERSION="$VERSION" sh octostore-install.sh

install -m 600 /dev/null ./octostore.tokens
printf 'ops:%s\n' "$(openssl rand -hex 32)" > ./octostore.tokens

BIND_ADDR='127.0.0.1:3000' \
STATIC_TOKENS_FILE='./octostore.tokens' \
DATABASE_URL='./octostore.db' \
octostore

curl http://localhost:3000/health

The server default is 0.0.0.0:3000; this first-run command overrides it to loopback. Configure TLS, network policy, and durable secret storage before exposing the service. The supported topology is one OctoStore process with one SQLite database, not an HA consensus cluster.

Local HTTP registration is disabled by default. A temporary LOCAL_REGISTRATION=true bootstrap requires an explicit numeric loopback bind and no OAuth or static-token source. Usernames are unique case-insensitively across local, static, and OAuth identities; collisions return 409 without reissuing the existing token, and ambiguous legacy databases fail startup. Disable registration after enrollment.

Safety model.

  • Terms are monotonic across restarts. The next fencing term is persisted before an acquisition is returned.
  • Leases recover from crashes. A vanished process stops renewing and loses authority after expiry.
  • Election tokens are bearer capabilities. Do not log them or put them in URLs.
  • Room IDs are not access controls. Use generated IDs and self-host when room discovery or traffic must be private.
  • Election admission is rate limited per client. Status, renewal, and resignation stay available so load cannot strand a current leader.
  • Locks are advisory. Downstream systems should be idempotent and reject stale fencing terms where possible.
  • Webhook destinations are public by default. HTTPS callbacks reject localhost plus private, link-local, and reserved literal or DNS-resolved addresses on every delivery attempt. Redirects are never followed.
